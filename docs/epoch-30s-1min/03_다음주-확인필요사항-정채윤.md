## 1. 소빈한테 (앱·프론트 쪽)

### 1-1. 모델 입력 격자를 1분으로 바꿔도 되는가 ★가장 중요

`interface-schema-전처리-프론트.md` 3-2절에 "**30초 epoch로 분할**"로 합의돼 있다
(확정 항목 #2: 마지막 조각도 포함). 이번에 1분 버전은 만들었지만, **합의 문서를 아직 안 고쳤다.**
소빈이 1분으로 바꾸는 걸 확정해야 문서·구현이 한 방향을 보고 간다.

### 1-2. 앱 export 격자(`EPOCH_MS`)는 30초 그대로 둘 것

소빈 앱의 `HealthModels.kt` 에 `const val EPOCH_MS = 30_000L` 이 있고 `EpochAggregator` 가
`epochIdx` 시각 좌표로 쓰고 있다. `selfCheck()` 주석에 이미 "night 어긋나면 F1(macro) −0.210,
Kappa −0.222, 에러 메시지 0줄" 이라고 적혀 있다.

**export 는 30초 유지**하고 **모델 입력만 1분**으로 갈라 두는 게 안전하다고 본다.
이렇게 하면 화면 기록 그래프와 Sleep-EDF 정답 join 이 둘 다 30초 기준을 유지한다.

소빈 확인 사항:
- 화면에서 "모델 계산 1분 / 기록 표시 30초" 가 혼동되지 않게 라벨 처리가 필요한가
- `MainActivity` / `SleepStageChart` / `Exporters` 가 `AnalysisResult` 새 필드 4개 때문에
  컴파일 문제 없는지 (기본값이 있어서 문제없을 것으로 보이지만 앱 빌드 확인이 필요)

### 1-3. Sleep-EDF 평가 파이프라인에 1분 → 30초 역집계 추가

소빈 #2는 "Sleep-EDF 30초 epoch 정답"으로 confusion matrix / F1 / kappa 를 뽑는 파이프라인이다.
1분 모델을 거기에 바로 붙이려면 각 30초 정답 epoch 를 대응하는 1분 값으로 되돌리는 규칙이 필요하다.
(1분 안에 정답 stage 가 두 개면 다수결 등)

**이 규칙을 정하지 않으면 1분 모델 성능을 못 잰다.** 이번 주 MVP 화면 확인은 1분으로 해도
무방하지만, 발표자료에 성능 수치를 올리기 전에는 반드시 정해야 한다.

## 2. 서윤 언니한테 (모델 쪽)

### 2-1. Hybrid 모델 확정 시점 — 임시 Two-Process 교체 시점

`SleepAnalysisPipeline` 의 `recommendation` 은 여전히 `null` ("준비 중")이다.
Hybrid 모델이 나오면 `recommendation` 과 `futureS` 를 교체한다.
1분 버전으로 정리했으니, 교체 시 epoch 인자만 맞춰 넘기면 된다.

### 2-2. C_sleep 의 phaseRef 가 epoch 간격에 예민하다

검증에서 30초 → 1분으로 바꾸니 `phaseRef` 가 조금 어긋나 C_sleep 가 0.0018 만큼 달랐다(진폭 0.15 대비 1.2%).
Hybrid 모델에서 C 나 리듬 위상을 결과값으로 쓴다면 **epoch 간격을 고정하고 그 기준으로 보고서를 쓰는 게 맞다.**
안 정하면 "같은 사람이 시간대만 바꿨는데 리듬 위상이 달라진다"가 생긴다.

### 2-3. epoch 간격을 모델 입력이 아니라 결과 해상도로 볼지

이번 1분 전환은 **입력 격자**만 바꿨다. 만약 의도가 "그래프를 덜 촘촘하게"였다면,
`scHistory` 전달 필터(10~15분)로도 되므로 epoch 를 안 바꿔도 된다.
목적이 무엇이었는지 확인해야 불필요한 변경이 안 남는다.

## 3. 혜지한테 (데이터 쪽)

### 3-1. 심박·걸음 CSV 확보 일정

`CsvFileSource.readHeartRate()` / `readSteps()` 가 지금 빈 목록을 반환한다. 원본 확보되면
파싱 로직을 넣으면 된다. 1분으로 바뀌면서 이쪽 요구사항이 조금 달라진다.

> **심박은 1분 격자에서 빈칸이 많아진다.** 데이터셋마다 심박 샘플 간격이 수십 초라,
> 30초 칸엔 대체로 1~2개가 들어가는데 1분 칸엔 1~4개 들어간다. 오히려 1분이 유리한 쪽이다.
> 걸음은 원래 10분 구간 합계로 오므로 1분 배분에서 값이 0으로 반올림될 수 있다.
> **걸음을 1분으로 배분할지, 걸음은 10분 합계를 그대로 쓸지 정해야 한다.**

### 3-2. Walch wearable baseline (#3) 진행 상황

이번 주 채윤 담당 #3(Walch wearable baseline) 이 남아 있다. 1분 전환 작업과 별개 트랙이므로
다음 주 초에 별도로 시작해야 한다. epoch 를 1분으로 바꿨으니까, Walch 모델 입력 epoch 규격도
1분 기준으로 통일할지 30초로 둘지 정해두면 중복 작업을 피한다.
